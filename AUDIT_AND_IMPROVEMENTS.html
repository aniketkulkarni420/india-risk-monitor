Design + Data Presentation Audit

What's wrong with IRM today, and how to fix it without a full rebuild.

For Aniket Kulkarni · 17 May 2026 · 14 findings · brutal, devil's-advocate · approval-pending

The complaint is real. The dashboard has 70 metrics, no typography hierarchy, six competing colours, and no answer to "what do I look at first?" — so users see everything and absorb nothing. This audit covers the eight failure modes underneath that complaint, proposes a specific fix for each, and shows the trade-off you'd be approving. You decide what to fix and in what order — nothing changes in the live code until you do.

Three findings that, if fixed, eliminate ~80% of the overload complaint

  1. Install a typography hierarchy (Finding 1) — there is currently no H1, weak H2, no scale ratio above ~1.6×. Premium tools live at 8–14× ratios. This is a CSS-only fix with disproportionate impact.
  2. Cut the home view from ~70 visible metrics to 5–8 (Finding 3) — most metrics on the live home don't drive a decision and shouldn't be there. They should still exist, just inside drill-downs or search.
  3. Reduce the visible colour palette from 6+ to 3 grays + 1 accent (Finding 4) — colour is currently noise, not signal. Restore semantic meaning by using colour sparingly.

Estimated effort to ship all three: ~14 hours. Everything else in this audit can be sequenced after.

FINDING 01

No typography hierarchy. Everything is the same size.

Critical

Current state

Looking at the live screenshots: page title (where? there isn't really one), section headings, metric labels, and metric values all live in a 12–22px range. The ratio between the largest and smallest meaningful type is roughly 1.6×. Premium products use 8× to 14×. Users have no visual cue for what to read first. The system font also lacks tabular numerals, so columns of numbers don't align vertically — even that adds load.

Why this is the root cause of "everything feels like noise"

Visual hierarchy is the primary mechanism the brain uses to skip 95% of a page and find the 5% that matters. Without hierarchy, the brain has to read every element to decide whether it matters. That's the cognitive overload. Colour, density, and content are downstream of typography.

Devil's advocate

"Aren't 72px scores for a dashboard excessive? Bloomberg doesn't do that."

Bloomberg is for users staring at 12 panels simultaneously — that's a different use case. IRM is read in 5-second glances by users coming from Twitter. The hero score is the headline; treat it like one.

Effort: 2–4h · CSS-only · no JS change · low risk
FINDING 02

No semantic H1. Section headings are visual chrome, not structural anchors.

Critical

Current state

Inspecting SectionFrame.mjs — section anchors are set on the <h2> element directly (the heading text itself carries id="flows"). There is no <h1> anywhere on the page. Screen readers, SEO, and browser jump-to-anchor all fail. Worse, the visual hierarchy follows: without a structural H1, designers and users alike have no anchor for "what is this page about?".

Proposed fix

  • One <h1> per page: "India Risk · 17 May 2026" at the top of the home view. Specific, dated, content-bearing — not "Dashboard" or "Overview" (per Design OS: avoid vague labels).
  • <h2> for each of the 6 sections: Flows · Macro · Real Economy · Freight · Market · Sectors.
  • <h3> for sub-clusters within sections (e.g. "Equity flows" + "Debt flows" inside Flows).
  • Move section anchor IDs to a wrapping <section id="..."> element — not the heading text. Lets the screenshot/audit tooling, scroll-to-section, and a11y all work correctly.
Effort: 1–2h · markup + a11y fixes · zero visual change · low risk

FINDING 04

Six colours visible simultaneously. Colour is noise, not signal.

Critical

Current state · count the colours on a single live screen

Looking at the desktop-1440 screenshot of the live home: I count red (shock pills, heatmap negatives), amber (high status), green (low status, heatmap positives), blue (the "info"/active state), cyan (some chart accents), plus the heatmap intermediates which add 3–4 more steps. That's 8–10 distinguishable hues across the screen.

The brain can hold ~4 colour categories in working memory before treating them as undifferentiated decoration. Once you have 8+ hues, the user stops reading them as semantic — they're just "visual texture." Which means the status pills stop conveying status.

Semantic exceptions used sparingly:

  • Shock red (#b91c1c) — only for SHOCK status. If 3 cards show shock, something's wrong with the system.
  • Safe green (#15803d) — only for "verified positive" (e.g. the freshness dot). Not for "low risk" status (that's just neutral — absence of risk).
  • Evidence blue (#1d4ed8) — for methodology, source links, "show me how" affordances.

Heatmap collapses from 8 steps to 3 steps: better than baseline · baseline · worse than baseline. Removes the "is this 7% better or 9% better?" cognitive question — humans can't read that off colour anyway.

Devil's advocate

Trading platforms (TradingView, Bloomberg) have one screen the user lives on for 8h. IRM is a 5-second glance from a phone. FINDING 05

No focal point. Everything competes for attention equally.

High

Current state

The hero shows the IRS score, but it's roughly the same visual weight as the section header below it, the driver tiles around it, and the topbar logo above it. Premium dashboards have one element 4–10× larger than everything else — the focal point. IRM has no focal point.

Proposed

Make the IRS score the unambiguous focal point: 72–96px display number, centered top, with one short sentence of human-language context underneath. Everything below is supporting evidence. The 6 drivers become a compact row, not 6 hero-weight tiles.

Eye-tracking rule of thumb: if you blur the page and squint, you should see one bright object first. The current home view has 6–8 bright objects. The proposed has one.

Effort: 3–4h · component restructure of Hero + Driver row · low risk
FINDING 06

Data presentation: misleading deltas, missing sources, unit-less numbers.

High
  • MoM% on bounded composites is mathematically misleading. "+20% MoM" on a 50→60 score reads as "fund up 20%" — but the score is bounded 0-100. Show point-change instead: "+10 pts · 1mo".
  • Sources visible only inside drawers, not on the metric face. Per the Design OS, financial-product trust requires source + "as on" date on every data point. Move source to the metric card itself (small, muted, but visible).
  • Unit suffixes inconsistent. "₹ 100 cr", "Rs 100 Cr", "₹100 crore", "100 cr" all appear. Pick one canonical: "₹100 cr" with thin space.
  • Percentages and decimals mixed without tabular alignment. 7.05% next to 86.4 next to 12 in the same column without right-alignment + tabular nums = visual scrambling.
  • "As on" timestamps absent on individual metrics. The user sees a number with no idea if it's from 4 min ago or 4 days ago.
Effort: 6–8h · formatter rewrite + per-metric layout edits · low risk
FINDING 07

Mode-fit error: IRM is built like Mode 4 (marketing) but should be Mode 3 (cockpit).

High

Per the Aniket Design OS, Mode 3 dashboards prioritise: compact, signal-first, timestamped, source-backed, calm-but-alert, cockpit-like. Mode 4 marketing pages prioritise: persuasive, decorative, atmospheric, broad-stroke.

Today's IRM has marketing patterns: prominent score, decorative gauges, large sparkline shapes, atmospheric dark theme, narrative paragraphs in the hero. It's missing cockpit patterns: "what changed" panel, severity badges with text (not just colour), confidence dots (separate from severity), watchlist visible, per-card source + as-on, action classifier ("monitor / watch / act").

The fix is structural, not cosmetic. The home should be a "what needs your attention this morning" panel (the Mode-3 cockpit pattern), with the score as context below — not the other way around. This connects to Findings 1, 3, and 5: solving them together actually flips the mode.

Effort: 8–12h · architectural · medium-high risk (changes the mental model)
FINDING 08

Status pills + sparklines on every metric = 50+ tiny attention-magnets.

High

With ~70 metrics on the home, you have ~70 status pills and ~70 sparklines. Each is "claim to attention" — eye darts across the page collecting them. None gets read as semantic. Status pills become decoration; sparklines become wallpaper.

Proposed

  • Status pills only on the metric face if status is non-neutral. 50 of 70 metrics are LOW/MED on a typical day — show the pill only for HIGH/SHOCK. Calm pills disappear. The page goes from 70 pills to 5–10.
  • Sparklines move to drill-down by default. Replaced on the home with a single point-change number ("+0.6 wk", "−2 pts mo") — same information, 95% less ink.
  • Exception: the 8 watchlist + signal cards keep their sparkline as part of the card body (high-value space).
Effort: 3–4h · conditional render + component prop · low risk
FINDING 09

Drawers exist but are invisible. Users don't know they can click.

Medium

The 9D inline-expand pattern is shipped — every metric row is clickable. But there's no visible affordance. No chevron, no hover-state hint, no subtle "→" on hover. Users who don't know about the drawer pattern see a static page. The data behind the rows might as well not exist.

Proposed

  • Add a tiny chevron (▸) at the end of every expandable row. Light grey, 11px. Rotates to ▾ when expanded.
  • On hover: the row background shifts to surface-2 and the chevron darkens. Cheap, clear, no animation overhead.
  • First-time-user only: a single tooltip on the IRS score saying "Click any metric for details" — dismissable, never shown again.
Effort: 2h · CSS-only + one-time onboarding tooltip · low risk
FINDING 10

Mobile is reflowed desktop, not mobile-native. 360px is broken.

Medium

Looking at the mobile-360 screenshots: section headers truncate, sparklines compress to unreadability, status pills wrap, and the page is 11,672px tall — that's ~16 viewport-heights of vertical scroll. Mobile-first per Design OS, and 80% of users in India probably open this on a phone first.

Proposed (mobile-first, not "mobile fix")

  • Tab-based section navigation instead of vertical stack. Each section a single screen of content — no scroll between sections, swipe-left for next section.
  • Card layouts replace tables. Each metric a card, full-width, scannable in one fixation.
  • Hero score takes the full first screen on phone. Below: 3 "what changed" cards. Section tabs at bottom (thumb-reachable).
  • 360px tested as the default, not the edge case.
Effort: 12–16h · separate mobile pass after desktop redesign · medium risk
FINDING 11

No "what changed since I last looked" panel. Every visit is a fresh full-scan.

High

The Design OS lists this as the #1 priority for Mode-3 cockpits and IRM has nothing for it. Every time a user opens IRM, they have to re-scan all 70 metrics to figure out what's different from yesterday. This is the single biggest cognitive-load lever.

Proposed

A "what changed" panel at the top of the home view. Driven by data the system already has — _composite_was (prior values) and timestamps. Shows 3–5 cards: which metrics moved most meaningfully since the user's last visit (stored in localStorage). Each card is a Mode-3 signal card (fact / interpretation / severity / source / suggested action).

Side effect: calm days show 0–2 cards; chaos days show 5+. The home view's "weight" naturally tracks the state of the world. No visual redesign required — content density automatically reflects reality.

Effort: 6–8h · localStorage "last visit", change-detection logic, signal-card component · medium risk

Dark theme is wrong default for Indian retail/HNI audience.

Medium

Summary: light default + dark opt-in toggle, because every other Indian finance platform (Moneycontrol, Tickertape, Zerodha, Groww, Smallcase, NSE/BSE) is light. FINDING 13

Hero narrative is news-journalism, not tool-language.

Low

The current hero has a paragraph or two of narrative ("Strait of Hormuz still closed. Oil pressure easing as tanker rates retreat. India risk holds at medium."). That's a news intro. Tools state numbers and trust the user to interpret. The narrative belongs in a "today's note" sidebar or a daily-brief email, not the home screen of a real-time dashboard.

Proposed

  • Replace the narrative paragraph with one short clause tied to the score: "Medium · Hormuz crisis driving oil pressure." 8 words max.
  • Move the full narrative to a "morning brief" link in the footer — opens an editorial-style daily note (Mode 1/2 aesthetic, not Mode 3).
  • Numbers speak; the tool doesn't editorialise.
Effort: 1h · copy edit + layout · zero risk
FINDING 14

Sectors section is a 15-row ranked list. Unscannable. Unactionable.

Medium

15 sectors in a vertical list with status pills — the user has to read all 15 to know which 3 matter. Phase 3 picker had this as an open decision: "4D color grid (treemap-like) + 'Show as table' toggle" — already designed in principle, not yet built.

Proposed

  • Default view: 4D color grid (one tile per sector, sized by index weight, coloured by 4D pressure: macro/flows/freight/real-econ).
  • Toggle to ranked-list view for power users who want to scan top-to-bottom.
  • 9D drawer per sector for detail.
  • Below the grid: a one-line summary — "3 sectors red (Banks, IT, Realty) · 9 amber · 3 green."
Effort: 5h · per Phase 3 picker estimate · medium risk (new component)

Devil's-advocate counter-arguments to the whole audit

Counter 1 · "You're telling me to throw away 70 metrics of hard work."

No metric is thrown away. They move to drill-down, search, or section-level pages. The work is preserved; only the home view changes. A user who wants fastag_toll can still get to it in ≤3 clicks — they just don't see it in the first 5 seconds.

The metrics aren't the product. The decision-velocity is the product.

Counter 2 · "Simplification will make it feel less like a 'serious institutional tool' and more like a 'consumer app'."

The opposite is true in 2026. Bloomberg's web product, Refinitiv, even Goldman's GS Marquee — all moved toward restraint, fewer pixels per square inch, premium typography, single accents. The "more visible data = more serious" instinct is from 2012. Today, restraint signals confidence; clutter signals "we don't know what's important."

Premium institutional in 2026 looks like Linear, not like a Bloomberg circa-2008 screenshot.

Counter 3 · "What if users don't actually feel overloaded? Maybe Aniket is overcorrecting."

Possible. But the audit isn't only validated by user complaints; it's validated by design-OS-level principles you already wrote down — one job per screen, one CTA, the 5-second rule, max 3 visual emphasis levels, max 7 metrics. The current product fails all of these. Even if no user has said "overload" out loud, the design is structurally overloaded by its own author's standards.

The audit is grading against your own rubric, not mine.

Counter 4 · "Why not just A/B test instead of redesigning?"

A/B testing on a free public dashboard with no auth and ~unknown user count gives weak signal. You'd need ~10k users per variant per week to read out anything. IRM probably has under 1k MAU at this stage. A/B is the right tool when traffic is dense; principles are the right tool when traffic is sparse.

Ship the simplification; measure (via session-length, repeat-visit, scroll-depth) after.

Counter 5 · "Why is the audit document itself so long? Isn't that hypocritical?"

Sharp point. The audit doc is long because each finding needs a defensible position and a counter-argument — and because you asked for ultrathink and brutal. The product itself should be the opposite. Audit doc = essay. Product = haiku.

Different artefacts, different constraints. (And yes, this doc could be 40% shorter and lose nothing.)
